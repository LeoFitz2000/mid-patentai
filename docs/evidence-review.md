# 证据定位与复核

0.2.0第二阶段修正原文位置与复核可追溯性，保留现有人工关卡。程序检查的是引文、字段和输入一致性，不自动证明语义支持、同一方案或专业结论。

## 原文位置与快照

新获取或人工录入的快照为 `snapshot_schema_version=2`。段落保留内部 `id`、原文位置 `source_location` 和实际HTML节点的 `source_anchor`。权利要求优先使用节点的 `num`，缺少时读取正文开头的编号；说明书优先使用段号或正文的方括号段号。原文无编号时明确写“快照内第几段”，不生成一个看似原文的编号。

网页报告显示原文位置，已有锚点时链接到该节点，同时保留内部ID。解析器找到权利要求和说明书仅记录 `parsed_complete` 结构提示，`complete` 不因此变为人工确认。

旧快照按原有字段与序列化方式校验原哈希，原文件不修改。新定位信息必须进入第2版快照及其哈希。旧报告可继续查看，但旧 `claim-2` 等只显示为快照内部编号，不自动解释为“权利要求2”；重新解析后需要重新复核。

## 候选与最终复核

自动定位、模型候选在单独区域显示，来源分别记录为 `auto`、`model`；旧来源未知时保留 `unknown`。最终复核表初始状态为未知，引文、方案编号和复核说明为空，完整性不预勾。

可以选择候选要素并点击“采纳所选候选引文”。这只复制引文、位置和候选来源，不确认披露状态、方案编号或说明。自行编辑引文或位置时来源改记为 `human`；该标记描述录入来源，不证明专业正确。

人工填写披露状态与说明。修改状态、引文、位置或方案编号而没有更新原说明时，旧说明不再进入判断。整段引文会提示核查限定，但不硬性禁止：某些有效证据确实需要多句上下文。

完整披露风险还需要同一方案说明和原文位置，所选位置覆盖各条披露引文，并保留充分公开的确认。编号相同只是字段一致性，不是程序完成了语义判断。

## 复核记录与失效

`DocumentReview` 记录 `reviewer`（自填姓名或代号）、带时区的 `reviewed_at`、`input_hash`、同一方案说明和依据位置。时间仅在点击提交时记录；模型建议没有人工身份、提交时间或确认状态。

输入绑定覆盖技术要素、基准日、快照哈希及本次复核内容、确认项、身份和时刻。改动任何绑定内容会使旧复核失效；网页编辑后清除相应确认，重新提交后才可导出新报告。系统不核验操作人的真实姓名、专业资质，也不提供密码学身份认证。

新报告使用 `report_schema_version=2`，JSON分别保存 `candidate_reviews` 与最终 `reviews`。旧复核缺少身份、时间或绑定时，当前规则要求重新复核，不补造历史记录。

合成评测夹具为新字段提供明确标为模拟的身份、固定时间和绑定；不是给历史真实案件补人工确认，参考标签保持不变。检索覆盖、相关性和真实专业判断质量仍需后续单独验证。
